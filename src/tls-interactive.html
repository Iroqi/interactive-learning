1加密基础

对称加密（AES）快但密钥要共享；非对称加密（RSA/ECC）慢但能解决密钥分发；哈希（SHA-256）不可逆，用于完整性。TLS 用混合加密：握手阶段非对称交换密钥，数据传输阶段用对称加密。

对称: AES/ChaCha20 - 快，双方共享密钥
非对称: RSA/ECDHE - 慢，解决密钥分发
哈希: SHA-256 - 完整性/指纹
混合: 非对称握手 → 对称传输

2证书与信任链

服务器公钥由CA 签名的证书背书。信任链：根 CA → 中间 CA → 服务器证书。浏览器内置根证书，验证链上每个签名。自签名证书无法链到根，浏览器告警。

根 CA (浏览器内置)
 └─ 中间 CA
     └─ 服务器证书 (CN=example.com, 公钥, 有效期)
验证：链式验签 + 域名匹配 + 有效期

3TLS 1.2 握手

TLS 1.2 握手：① ClientHello（版本/随机数/密码套件）；② ServerHello + 证书；③ 客户端验证证书并发送密钥交换（预主密钥）；④ 双方各自派生会话密钥；⑤ ChangeCipherSpec + Finished 确认。随后数据用对称密钥加密。

Client ── ClientHello ──→ Server
Client ←─ ServerHello+证书 ← Server
Client ── 密钥交换(预主密钥) ──→ Server
双方派生会话密钥
Client ⇄ Finished 确认
之后：对称加密传输

4TLS 1.3 的改进

TLS 1.3：① 1-RTT——ClientHello 直接携带密钥共享（Key Share），一个往返完成握手；② 移除 RSA 密钥交换与弱套件；③ 支持 0-RTT 会话恢复（重连更快）；④ 强制前向保密（ECDHE）。

TLS 1.3 握手 (1-RTT):
Client ── ClientHello + key_share ──→ Server
Client ←─ ServerHello + 证书 + Finished ← Server
双方直接派生密钥，开始加密传输

6证书验证清单

浏览器验证书四件事：① 信任链（签名链到内置根）；② 域名（SAN/CN 匹配访问的 host）；③ 有效期（notBefore/notAfter）；④ 吊销状态（CRL/OCSP）。任一失败 → 不可信。

✓ 签名链到受信根
✓ 域名在 SAN 中 (example.com)
✓ 当前时间在有效期内
✓ 未被吊销
任一失败 → 浏览器告警/拒绝

7HTTPS 与安全细节

HTTPS = HTTP over TLS。安全细节：HSTS 强制 HTTPS；证书固定（防中间人）；混合内容（HTTPS 页面加载 HTTP 资源）会被浏览器拦截；降级攻击（强制回到 HTTP）用 HSTS 防。

HSTS 头: Strict-Transport-Security: max-age=31536000
→ 浏览器强制 HTTPS，防降级
混合内容: https 页面里的 http 脚本/图片 → 拦截
证书固定: 校验固定指纹，防自签中间人

8常见攻击与防护

① 中间人：证书验证是唯一防线（自签/钓鱼 CA 必须告警）；② 证书过期：运维巡检 + 自动续期（ACME）；③ 弱套件/旧协议：禁用 TLS 1.0/1.1、禁用 RC4/3DES；④ 客户端忽略证书错误（curl -k 生产禁用）。

防护基线：
- 证书自动续期 + 有效期监控
- 仅启用 TLS 1.2+/TLS 1.3，禁用弱套件
- 客户端不跳过证书验证 (禁 -k)
- 私有 CA 管理好根私钥
