1Compose：多容器编排声明

docker 命令管单个容器；Compose 用一份 compose.yaml 声明整个栈（多个服务、网络、卷），一条 docker compose up -d 全部拉起。核心概念：services（容器）、networks（互联）、volumes（持久化）。

services:
  web:
    image: nginx:alpine
    ports:
      - "8080:80"
  db:
    image: postgres:16

练习：Compose 概念

2services：每个服务一个容器

顶层 services 下每个键是一个服务名；服务必选 image（或 build）。服务间默认在同一个网络，可直接用服务名互相访问。

services:
  api:
    image: my-api:1.0
    build: ./api          # 或用本地 Dockerfile 构建
    environment:
      DB_HOST: db          # 服务名即主机名
  db:
    image: postgres:16

4端口映射与卷

ports: "宿主机:容器" 把容器端口暴露到宿主机；volumes 持久化数据：命名卷（data:/var/lib/db，需在顶层 volumes 声明）或绑定挂载（./code:/app 指向宿主机目录）。

services:
  app:
    image: my-app
    ports:
      - "8080:80"          # 宿主 8080 → 容器 80
    volumes:
      - ./code:/app        # 绑定挂载（开发热更新）
      - data:/var/lib/data  # 命名卷
volumes:
  data:

6依赖与健康检查

depends_on 控制启动顺序（"等 db 先起"）；healthcheck 给服务定义健康探针；networks 让服务只加入需要的网络（默认网络以外可自定义）。

services:
  app:
    image: my-app
    depends_on:
      - db            # 先启动 db
    networks:
      - front
  db:
    image: postgres:16
    healthcheck:
      test: ["CMD-SHELL", "pg_isready"]
      interval: 5s
      timeout: 3s
      retries: 3
    networks:
      - front
networks:
  front:

8常用命令

生命周期：up -d 后台拉起 → ps 查看 → logs -f 看日志 → down 停止并（默认）移除网络。卷默认保留，数据不丢。

$ docker compose up -d          # 构建并后台启动
$ docker compose ps             # 服务状态
$ docker compose logs -f app    # 跟踪某个服务日志
$ docker compose down           # 停止并移除容器/网络（保留卷）
$ docker compose down -v        # 连命名卷一起删除
