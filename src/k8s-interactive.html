1集群架构：控制平面 × 工作节点

Kubernetes（K8s）是一个容器编排平台。集群由控制平面（大脑）与工作节点（肌肉）组成：控制平面做决策，工作节点跑容器。

控制平面（Control Plane）

  • kube-apiserver — 所有操作的唯一入口
  • etcd — 集群状态存储
  • kube-scheduler — 决定 Pod 跑在哪个节点
  • kube-controller-manager — 维持期望状态

工作节点（Worker Node）

  • kubelet — 节点上的"眼睛和手"
  • kube-proxy — 维护网络规则
  • 容器运行时 — 真正拉起容器（containerd 等）

2kubectl：集群的遥控器

kubectl 是与集群交互的命令行工具。最常用的三个命令：kubectl get（查）、kubectl describe（详查）、kubectl create/run（建）。

命令作用
kubectl get pods列出所有 Pod
kubectl describe pod <name>查看 Pod 详情与事件
kubectl create deployment <name> --image=<img>创建 Deployment
kubectl get nodes查看集群节点

3Pod 与标签选择器

Pod 是 K8s 的最小调度单元（一个或多个容器）。标签（label）是键值对，选择器（selector）用标签筛选资源——这是 K8s 一切关联（Service→Pod、Deployment→Pod）的基石。

kubectl label pod web-6d8c7b5f4f-zm2kq app=web tier=frontend
kubectl get pods -l app=web
NAME                          READY   STATUS    RESTARTS   AGE
web-6d8c7b5f4f-zm2kq         1/1     Running   0          16m
web-6d8c7b5f4f-vh3nw         1/1     Running   0          16m

练习：选择器语义

记忆：kubectl label 是打标签，kubectl get -l 是筛标签，两者不同向。

4Deployment：声明式部署与滚动更新

Deployment 声明"我要 3 个副本的 nginx"，控制器负责实现。更新镜像时默认滚动更新：新副本先起、就绪后再替换旧副本，全程不中断服务。

kubectl create deployment web --image=nginx:1.25 --replicas=3
kubectl set image deployment/web web=nginx:1.26   # 触发滚动更新
kubectl rollout status deployment/web             # 查看进度
任务：在模拟器中执行 kubectl set image deployment/web web=nginx:1.26，再执行 kubectl rollout status deployment/web 完成滚动更新，解锁里程碑。

5Service：让 Pod 可以被访问

Pod 会随时重建、IP 会变。Service 提供一个稳定的虚拟 IP 与 DNS 名，通过 selector 把流量转发到一组 Pod。三种常用类型：

类型访问范围场景
ClusterIP集群内部微服务互相调用
NodePort集群外部（节点端口）快速对外暴露测试
LoadBalancer集群外部（云负载均衡）生产对外服务

练习：选择正确的 Service 类型

6自愈：探针与重启策略

K8s 会自动"修复"：容器崩溃会重启（restart）、节点宕机会把 Pod 重建到别处。探针（probe）用于判断容器是否健康：

探针问什么失败后果
livenessProbe进程还活着吗？杀掉并重启容器
readinessProbe能开始接收流量吗？从 Service 端点摘除，不重启
startupProbe启动完成了吗？保护慢启动应用

练习：选探针

7ConfigMap 与 Secret：配置与密文

配置不该写死在镜像里。ConfigMap 存普通配置，Secret 存敏感信息（密码、令牌，存储时 base64 编码）。两者都可以通过环境变量或挂载文件注入 Pod。

kubectl create configmap app-config --from-literal=APP_ENV=production
kubectl create secret generic db-pass --from-literal=PASSWORD=s3cret
# Pod 中引用：
env:
- name: APP_ENV
  valueFrom:
    configMapKeyRef: { name: app-config, key: APP_ENV }

练习：选择正确说法

8存储：PV / PVC 与持久化

容器内文件在 Pod 重建后消失（临时卷）。持久化方案：PV（PersistentVolume，管理员准备的存储）、PVC（PersistentVolumeClaim，用户申请），PVC 绑定 PV 后挂载进 Pod。常用卷类型：emptyDir（临时）、hostPath（单节点）、云盘（跨节点共享）。

apiVersion: v1
kind: PersistentVolumeClaim
metadata: { name: data-pvc }
spec:
  accessModes: [ReadWriteOnce]
  resources: { requests: { storage: 5Gi } }

练习：选卷
