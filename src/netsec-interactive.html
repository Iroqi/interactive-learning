1威胁模型：CIA 三元组与信任边界

安全的目标是保护数据的 CIA：机密性（Confidentiality）、完整性（Integrity）、可用性（Availability）。威胁模型从"谁是攻击者、什么资产、什么入口"出发，画出信任边界——边界两侧的输入都不可信。

# 安全第一原则
1. 永远不要信任用户输入（前端传来的、URL 里的、表单里的）
2. 永远不要信任任何"看不见"的请求来源
3. 输出到不同上下文（HTML/JS/SQL/URL）必须分别转义
4. 最小权限：只给完成工作所需的最少权限

2XSS 跨站脚本

5SSRF 服务端请求伪造

服务端拿着用户提供的 URL 去发请求。攻击者可借此访问内网（metadata 服务、内部管理口）——因为请求来自"受信任的服务端"。下面哪里危险？

6认证与授权缺陷

认证是"你是谁"（登录），授权是"你能干什么"（权限）。常见缺陷：只在客户端隐藏按钮、接口不做权限校验、弱会话/可预测 Cookie、密码明文存储。下面哪里危险？

# 后端：管理员接口 —— 只靠前端"隐藏"来保护
@app.route('/admin/delete_user')
def delete_user():
    uid = request.args['uid']
