1事务：要么全成，要么全败

事务把多条 SQL 打包成一个原子单元。ACID：Atomicity（原子性：全成或全败）、Consistency（一致性：约束始终满足）、Isolation（隔离性：并发互不干扰）、Durability（持久性：提交后不丢）。

BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;  -- 要么都成功
COMMIT;   -- 要么 ROLLBACK 全部回滚

练习：ACID

2判读器：脏读

脏读：T2 读到 T1 未提交的数据，T1 回滚后 T2 读到的是"幽灵数据"。唯一允许脏读的隔离级别是 Read Uncommitted。

T1: UPDATE orders SET amount = 999;   -- 未提交
T2: SELECT amount FROM orders;         -- 读到 999（脏读!）
T1: ROLLBACK;                          -- 数据恢复，T2 白读

判读：上述"读到未提交数据"发生在哪个隔离级别？

3判读器：不可重复读

不可重复读：同一条 SELECT 在事务内两次执行，结果不同——因为中间被其他已提交事务修改了。Read Committed 防止脏读，但允许不可重复读（每次读都取"当前已提交"快照）。

T1: SELECT amount FROM orders WHERE id = 1;   -- 100
T2: UPDATE orders SET amount = 200; COMMIT;    -- 已提交
T1: SELECT amount FROM orders WHERE id = 1;   -- 200（不可重复读!）

判读："同事务内两次读到不同已提交值"——Read Committed 允许它吗？

四个级别由弱到强，防的问题越来越多：

练习：矩阵记忆

5判读器：幻读

幻读：事务内两次范围查询（WHERE 条件），第二次多出了符合条件的行——其他事务插入了新行。Repeatable Read 保证已存在的行不变，但新插入的"幻影行"仍可能出现。

T1: SELECT COUNT(*) FROM orders WHERE amount > 100;   -- 2 行
T2: INSERT INTO orders(amount) VALUES (999); COMMIT;      -- 新行
T1: SELECT COUNT(*) FROM orders WHERE amount > 100;   -- 3 行（幻读!）

判读："范围查询多出幻影行"在哪个级别仍可能发生？

6实战判读：银行转账

账户扣款 + 入账必须原子且隔离。并发转账场景通常用 Serializable 或行锁 + RR：绝不允许读到中间态，也不允许余额凭空变化。

BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;

7判读器：组合场景

综合题：既要不读未提交数据，又要同一行两次读一致，还要容忍范围查询多行（可以接受幻读）——选哪个级别？

T1: 读行 A（需两次一致）          → 防脏读 + 防不可重复读
T2: 可更新已提交行、可插入新行    → 容忍幻读

判读：防脏读 + 防不可重复读、接受幻读，选？

8MVCC 与锁

MVCC（多版本并发控制）：每个事务看到自己的"快照版本"，读写互不阻塞——这是 MySQL InnoDB 实现 RC/RR 的方式。行锁/表锁：写写互斥；间隙锁（Gap Lock）锁住范围防插入（幻读）。

-- 写锁：其他写事务必须等待
UPDATE accounts SET balance = 0 WHERE id = 1;   -- 行 X 锁，未提交
-- 读：MVCC 快照，不阻塞
SELECT balance FROM accounts WHERE id = 1;       -- 读到自己的版本
