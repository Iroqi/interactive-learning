1JWT 结构：三段式

JWT = header.payload.signature，三段都是 Base64Url 编码后用点号连接。header 描述算法与类型，payload 放声明，signature 防篡改。它本身不是加密——任何人可解码读取，但改不了内容（改了就验签失败）。

2Header：算法与类型

{"alg":"HS256","typ":"JWT"}：alg 声明签名算法（HS256/RS256/ES256…），typ 固定 JWT。服务端必须按白名单校验 alg，不能盲信 header——攻击者可把 alg 改成 none。

练习：Header 判读

3Payload：标准声明

标准声明（claims）：sub（主题=用户 ID）、exp（过期时间戳）、iat（签发时间）、iss（签发者）、aud（受众）、nbf（生效时间）。自定义声明如 role、admin 也可放入。

{"sub": "1234", "name": "Alice", "role": "admin", "exp": 1730000000, "iat": 1729900000}

练习：声明语义

4Base64Url：URL 安全的编码

Base64Url 是标准 Base64 的变体：+ 换 -、/ 换 _、去掉尾部 =，保证 token 能在 URL/Header 里安全传输。解码后是 UTF-8 JSON。

5签名：防篡改

signature = HMAC(header + "." + payload, secret)（HS256 对称）或私钥签名（RS256 非对称）。服务端重算签名比对：一致 → 内容未被改过。签名不加密内容，只保证完整性。

练习：签名语义

6HS256：对称验签流程

HS256 用同一个 secret 签与验（对称）。流程：取 header.payload → HMAC-SHA256(secret) → Base64Url → 与第三段比对。secret 必须保密且足够强——弱密钥可被离线爆破（如 "secret"/"123456"）。

7过期与生效：exp / nbf / iat

exp（过期）：当前时间 > exp 拒绝；nbf（生效）：当前时间 < nbf 拒绝；iat 记录签发时间供审计。校验顺序：签名 → exp/nbf → 业务声明（sub/role）。

8JWT 常见漏洞与防护

① alg=none：把算法改成 none 去掉签名——服务端必须白名单校验 alg；② 弱密钥：HS256 弱 secret 可离线爆破；③ 算法混淆：把 RS256（公钥验）降级成 HS256（用公钥当 secret 伪造）；④ token 泄露：偷 token 即冒充，需 HTTPS + 短过期 + 刷新机制。

防护清单：服务端白名单校验 alg；secret 用 32+ 字节随机；RS256 验签只验签名不信任 header；token 不放 URL/日志；设置合理 exp。
