1RPC 与 gRPC 基础

gRPC 是高性能 RPC 框架：HTTP/2 传输（多路复用、双向流）、protobuf 二进制序列化（更快更小）、接口定义先行（.proto 生成客户端 stub 与服务端骨架）。客户端调用远程方法像调用本地函数。

syntax = "proto3";
service Greeter {
  rpc SayHello (HelloRequest) returns (HelloReply);
}

2Protobuf 定义

message 定义数据结构，字段有编号（编码用，不可随意改）、类型与标量（string/int32/bool...）。service 定义 RPC 方法。字段编号一旦发布就是协议的一部分——改编号会破坏兼容。

message Order {
  string id = 1;
  int32 qty = 2;
  bool paid = 3;
}
service OrderService {
  rpc Get (OrderId) returns (Order);
}

3四种方法类型

gRPC 支持四种调用形态：Unary（一问一答）、Server-streaming（一请求多响应）、Client-streaming（多请求一响应）、Bidi-streaming（双向持续流）。流式靠 HTTP/2 的流实现。

rpc A (Req) returns (Resp);          // unary
rpc B (Req) returns (stream Resp);    // server-streaming
rpc C (stream Req) returns (Resp);    // client-streaming
rpc D (stream Req) returns (stream Resp); // bidi

4拦截器链

拦截器在调用前后织入横切逻辑（日志、鉴权、限流、追踪）。调用链顺序：客户端拦截器按注册序 → 网络 → 服务端拦截器逆序 → 业务方法。返回时反向执行。

Client: A → B → ── HTTP/2 ── → Server: X → Y → 业务方法
返回: A ← B ← ───────────── ← X ← Y ← 返回值

5错误码、超时与重试

gRPC 状态码：OK / NotFound / Internal / Unavailable / DeadlineExceeded 等。deadline 是调用总超时；重试只对幂等/特定错误（Unavailable 等）做，且要配退避，防止惊群。context 贯穿调用链传递截止时间。

ctx, cancel := context.WithTimeout(ctx, 2*time.Second)
// Unavailable → 可重试（退避）
// InvalidArgument → 不重试（客户端 bug）
// DeadlineExceeded → 停止重试，直接失败
本节任务

7Channel、keepalive 与负载均衡

Channel 是到服务的连接池（HTTP/2 多路复用，一个连接并发多请求）。keepalive ping 探测空闲连接健康；客户端负载均衡（round_robin 等）在连接层面分发；流式调用负载均衡粒度更细。

channel = grpc.NewClient(addr, grpc.WithLoadBalancer(round_robin))
keepalive: ping 每 30s，超时检测断连重连

8生产实践

生产必做：TLS（gRPC 默认 TLS，禁用明文）、反射/健康检查（grpc-health-probe、grpcurl 调试）、拦截器统一鉴权与追踪、连接泄漏防护（用后关闭）、优雅停机（GracefulStop 处理在途请求）。
