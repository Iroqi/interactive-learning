1Nginx 架构：事件驱动的高并发之王

Nginx 采用 master 进程 + 多个 worker 进程模型：master 管配置与调度，worker 用事件驱动 + 非阻塞 IO处理连接，单 worker 可支撑数万并发。静态文件、反向代理、负载均衡是它的三大主场。

# nginx.conf 顶层骨架
worker_processes auto;

events {
  worker_connections 10240;
}

http {
  include       mime.types;
  # ... server 块都放在 http 内
}

练习：Nginx 架构

2配置层级：http → server → location

配置按上下文（context）分层：http（全局）→ server（一个站点/虚拟主机）→ location（URL 路径规则）。指令会继承：外层设的，内层没设就沿用。

http {
  gzip on;                      # 所有 server 继承
  server {
    listen 80;
    server_name example.com;
    location / {
      root /var/www/html;
    }
    location /api/ {
      proxy_pass http://backend;
    }
  }
}

练习：层级关系

4静态文件：root 与 try_files

root 定义站点根目录（root + URI = 磁盘路径）；index 指定目录默认文件；try_files 按顺序尝试文件，常用于前端 SPA 的"找不到就回退 index.html"。

location / {
  root      /usr/share/nginx/html;
  index     index.html;
  try_files $uri $uri/ /index.html;   # 路由回退到 SPA 入口
}

练习：root 与 try_files

5虚拟主机：一台机器跑多个站点

一个 server 块就是一个站点。Nginx 按 listen + server_name 匹配请求该交给哪个 server；server_name 支持通配（*.example.com）与精确匹配，精确 > 最长通配 > 默认。

server {
  listen 80;
  server_name api.example.com;    # 精确匹配优先
  location / { proxy_pass http://api-upstream; }
}
server {
  listen 80 default_server;       # 兜底
  server_name _;
  return 404;
}

练习：server_name 匹配

6反向代理与负载均衡

proxy_pass 把请求转发给后端；upstream 定义一组后端并支持轮询/权重等负载均衡策略。这也是 Nginx 作为网关最常见的用法。

upstream backend {
  server 10.0.0.11:8080 weight=3;
  server 10.0.0.12:8080;
}

server {
  listen 80;
  server_name app.example.com;
  location / {
    proxy_pass http://backend;
    proxy_set_header Host $host;
  }
}
任务：在校验器中加入 location / { proxy_pass http://backend; }（可一并声明 upstream），nginx -t 通过后解锁本里程碑。

7重定向：return 与 rewrite

return 301 https://$host$request_uri; 强制 HTTPS；rewrite 改写 URL 再继续匹配；return 更高效，能做的场景优先用 return。

server {
  listen 80;
  server_name example.com;
  return 301 https://$host$request_uri;   # HTTP → HTTPS
}
server {
  listen 443 ssl;
  # ...ssl_certificate 等
}

练习：重定向

8HTTPS：listen 443 ssl 与证书

启用 TLS 需要三件事：listen 443 ssl、ssl_certificate（证书链）、ssl_certificate_key（私钥）。再加安全头（HSTS、X-Frame-Options 等）把站点加固。

server {
  listen 443 ssl;
  server_name example.com;
  ssl_certificate     /etc/nginx/ssl/example.com.crt;
  ssl_certificate_key /etc/nginx/ssl/example.com.key;
  add_header Strict-Transport-Security "max-age=31536000" always;
}
任务：在校验器中把某个 server 改成 listen 443 ssl 并配上 ssl_certificate + ssl_certificate_key，nginx -t 通过后解锁本里程碑。
