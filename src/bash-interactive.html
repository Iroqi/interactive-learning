01脚本是什么

脚本 = 把命令行操作写进文件、按顺序执行。命令是一次性对话，脚本是可复用的自动化。

# 一个最简单的脚本
#!/bin/bash            # shebang：声明用 bash 解释器
echo "hello, world"
ls -la                    # 在脚本里可以调用任何命令
三步运行：chmod +x script.sh 赋予执行权限 → ./script.sh 执行（shebang 决定解释器）→ 或用 bash script.sh 直接解释运行。
常见误解：不是每个脚本都要写 shebang —— 但写成 #!/bin/bash 能保证用 Bash 而不是默认 shell 解释，避免语法差异踩坑。
可复用：一键重复执行多步操作 可编程：变量 / 判断 / 循环 可组合：调用任意命令

03参数与退出码

脚本可以接收参数：$1 $2 ...；$# 是参数个数；$@ 是所有参数；$? 是上一条命令的退出码（0 = 成功，非 0 = 失败）。

#!/bin/bash
echo "脚本名: $0，参数个数: $#"
echo "第一个参数: $1"
echo "所有参数: $@"
ls /no/such/dir
echo "上一条命令退出码: $?"   # 2（ls 失败）
习惯：脚本里用 $? 判断命令成败，配合 ||（失败时执行）和 &&（成功时执行）写出防御性逻辑。

04管道与重定向

管道 | 把前一个命令的输出接给后一个命令的输入；重定向把输出写进文件（> 覆盖，>> 追加，2>&1 合并错误流）。

cat project/logs/app.log | grep error | wc -l   # 错误行数
ls -la > filelist.txt                        # 覆盖写入
echo done >> filelist.txt                    # 追加写入
常见误解：2>&1 不是"错误码 2 合并到 1"，而是把错误输出流(2)重定向到标准输出流(1)；> 与 >> 的区别在于覆盖还是追加。
练习回到上方终端完成：cat project/logs/app.log | grep error（管道），再 echo ok > check.txt（重定向）—— 两条都跑过即可解锁里程碑
管道：cat project/logs/app.log | grep error
重定向：echo ok > check.txt，然后用 cat check.txt 验证

05条件判断

if + test（或 [ ]）判断条件：[ -f 文件 ] 存在且是普通文件，[ -d 目录 ] 是目录，[ "$a" = "$b" ] 字符串相等，[ $n -gt 10 ] 数值比较。

#!/bin/bash
if [ -f "app.js" ]; then
  echo "文件存在"
elif [ -d "app.js" ]; then
  echo "它是目录"
else
  echo "不存在"
fi                               # if 一定要以 fi 结束
为什么总是看到 [ 两边有空格？因为 [ 其实是一个命令（等价于 test），命令与参数之间必须用空格分隔 —— [ -f app.js ] 正确，[-f app.js] 会报错。

06循环

for 遍历列表，while 按条件重复，until 直到条件成立。批量处理文件、循环请求、生成配置都靠它。

# for 遍历
for file in *.log; do
  echo "处理 $file"
done

# while 按计数循环（C 风格也可用 $(( ))）
i=0
while [ $i -lt 3 ]; do
  echo "第 $i 次"; i=$(( i + 1 ))
done
练习补全脚本：遍历 1 2 3 并打印每个数字（注意引号里的展开）
#!/bin/bash
for in 1 2 3; do
  echo
done

07函数

函数把一段逻辑命名复用：myfunc() { ... }，调用即执行；函数内 $1 $2 是函数参数（不是脚本参数），用 return 返回数字状态码。

#!/bin/bash
deploy() {
  echo "部署到: $1"
  return 0
}
deploy production        # 调用函数，$1 = production
注意：函数必须先定义再调用；脚本从上到下执行，调用写在定义之前会报 "command not found"。

    脚本出问题时，先问三件事：权限（chmod）、语法（bash -n）、执行过程（bash -x 逐行打印）。

    bash -n script.sh 只查语法不执行 bash -x script.sh 逐行打印执行过程 set -e 命令失败即退出 变量务必加引号："$file" 
    #!/bin/bash
set -e          # 任何命令失败立即退出，避免错误蔓延
set -u          # 使用未定义变量即报错，抓出拼写错误

for file in /tmp/data/*.txt; do
  echo "处理: $file"   # 永远给变量加双引号
done
    黄金法则：能放进引号的地方都放进引号 —— 文件名含空格是脚本最常见的隐形杀手。set -euo pipefail 是许多生产脚本的标准开头。
