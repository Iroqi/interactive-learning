1镜像与层

镜像由只读层堆叠而成，每条指令产生一层；容器在镜像上加可写层。docker build 按 Dockerfile 从上到下逐条执行，生成不可变镜像。

FROM node:20            # 基础层
RUN npm install         # 层 2
COPY app.js /app/       # 层 3
CMD ["node", "app.js"]  # 层 4（元数据）
本节任务
  • 理解镜像 = 只读层堆叠 + 顶层可写容器层
  • 识别一条指令对应一层的对应关系

练习：层模型

2基础指令

FROM 基础镜像；RUN 构建时执行命令；COPY 从上下文拷文件；ADD 类似 COPY 但支持解压/URL；ENV/WORKDIR 设置环境与工作目录；EXPOSE 声明端口（仅文档）。

FROM python:3.12
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
ENV PYTHONUNBUFFERED=1
EXPOSE 8000
CMD ["uvicorn", "main:app"]
本节任务
  • 掌握 FROM/RUN/COPY/ENV/WORKDIR 各自职责
  • 注意 COPY 与 ADD 的差异

练习：指令语义

3ENTRYPOINT 与 CMD

CMD 提供默认命令（可被 docker run 参数覆盖）；ENTRYPOINT 固定入口（docker run 参数追加为它后面）。exec 形式 ["a","b"] 不经过 shell；shell 形式 a b 会先起 shell。

ENTRYPOINT ["python", "app.py"]   # 固定入口
CMD ["--port", "8000"]             # 默认参数，可被覆盖
# docker run img --port 9000 → python app.py --port 9000
本节任务
  • 区分 CMD（可覆盖）与 ENTRYPOINT（固定）
  • 掌握 exec 与 shell 两种形式

练习：入口语义

4多阶段构建

多个 FROM 构成多阶段：builder 阶段装全量依赖并编译，runner 阶段 COPY --from=builder 只拷产物，最终镜像小且安全。阶段可用 AS name 命名。

FROM golang:1.22 AS builder
WORKDIR /src
COPY . .
RUN go build -o /app/server

FROM alpine:3.20
COPY --from=builder /app/server /usr/local/bin/server
ENTRYPOINT ["server"]
本节任务
  • 理解多阶段：构建产物跨阶段传递
  • 最终镜像只含运行所需，体积更小

练习：阶段理解

5层缓存与失效

构建时命中的层会复用缓存。COPY 的源文件变化会导致该层及其后所有层失效——所以把少变化的依赖安装放前面、易变的代码放后面（先 COPY requirements 再 RUN install）。

# 坏：先 COPY . 会因每次代码改动使 npm install 全部重跑
COPY . .
RUN npm install

# 好：依赖层被缓存，代码改动只重建最后几步
COPY package.json .
RUN npm install
COPY . .
本节任务
  • 掌握缓存命中与失效规则
  • 理解"依赖前置、代码后置"的优化顺序

练习：缓存判断

6构建上下文与 .dockerignore

docker build . 把当前目录打包为构建上下文（默认发送给守护进程）；.dockerignore 排除 node_modules、.git 等，避免缓存失效与上下文膨胀。

# .dockerignore
node_modules
.git
*.log
.env
本节任务
  • 理解构建上下文的作用范围
  • 用 .dockerignore 排除敏感与体积大的文件

练习：上下文

7HEALTHCHECK / USER / 元数据

HEALTHCHECK 定义健康探针（容器编排据此重启/摘流）；USER 切换运行用户（安全最佳实践，避免 root）；EXPOSE 只声明不开放；LABEL 存元数据。

HEALTHCHECK --interval=30s CMD curl -f http://localhost:8000/ || exit 1
USER nobody
LABEL version="1.0" maintainer="ops"
本节任务
  • 理解 HEALTHCHECK 探针机制
  • 遵循非 root 用户运行的安全实践

练习：健康与安全
