1基础设施即代码：把云写成声明

Terraform 用 HCL 语言声明基础设施（"要什么"），而不是命令式地一步步操作（"怎么做"）。它维护一个期望状态，通过 plan 预览差异、apply 应用差异、destroy 清理资源。

# main.tf —— 声明一个 AWS 虚拟机
provider "aws" { region = "ap-southeast-1" }

resource "aws_instance" "web" {
  ami           = "ami-0abc123"
  instance_type = "t3.micro"
  tags = { Name = "web" }
}

练习：声明式 vs 命令式

2HCL 语法：块与属性

HCL 的核心是块：`类型 "标签" { ... }`。资源块 = resource "类型" "名称"；块内是 键 = 值 属性；值可以是字符串、数字、布尔或嵌套的 map/块。

resource "aws_security_group" "sg" {
  name = "web-sg"
  ingress {
    from_port = 80
    to_port   = 80
    protocol  = "tcp"
  }
}

练习：HCL 语法

4变量与输出：参数化配置

variable 块声明输入参数（可带 default 与 type），配置里用 var.名字 引用；output 块把资源属性暴露给调用方。这让同一份配置可以在 dev/prod 复用。

variable "instance_type" {
  type    = string
  default = "t3.micro"
}

resource "aws_instance" "web" {
  instance_type = var.instance_type
}

output "web_ip" {
  value = aws_instance.web.public_ip
}

5状态文件：Terraform 的"记忆"

terraform.tfstate 记录"现实世界长什么样"（已创建的资源与属性）。Terraform 靠它对比配置算出 diff。团队协作时状态要存到远程后端（S3/Terraform Cloud）并加锁，避免两人同时 apply 互相覆盖。

terraform init            # 初始化 & 配置后端
terraform plan            # 对比 配置 vs 状态 → 输出计划
terraform apply           # 执行计划 & 更新状态

练习：状态文件

6模块化：复用基础设施

module 块把一组资源封装成可复用单元（类似函数的"基础设施版"），通过输入变量参数化、output 暴露结果。一个团队可以维护"标准 VPC 模块""标准数据库模块"。

module "vpc" {
  source = "terraform-aws-modules/vpc/aws"
  name   = var.env
  cidr   = "10.0.0.0/16"
}

练习：模块

7隐式依赖：引用即依赖

当资源 A 的属性引用资源 B（如 aws_instance.web.vpc_id），Terraform 自动建立依赖并保证 B 先创建。这就是"隐式依赖"——不需要手动声明顺序。

resource "aws_instance" "web" {
  subnet_id = aws_subnet.app.id   # 引用 → 先建 subnet，再建 instance
}

练习：依赖

8destroy 与生命周期

terraform destroy 按依赖逆序销毁全部资源。生命周期保护：prevent_destroy = true 可阻止误删数据库等重要资源；create_before_destroy 让替换时先建新的再删旧的。

resource "aws_db_instance" "main" {
  # ...
  lifecycle {
    prevent_destroy = true
  }
}
