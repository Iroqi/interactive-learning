1tmux 是什么 · 为什么需要它

tmux = terminal multiplexer。它在终端里创建一个服务端管理的会话层：所有窗口、分屏、滚动缓冲都活在 tmux server 进程里，你的终端模拟器（iTerm / Terminal / SSH）只是连上去的"客户端"。SSH 断了、笔记本合盖了、网络抖了——重连后 tmux attach，一切还在原地。

# 没有 tmux：SSH 断开 → 进程全部 SIGHUP → 跑了 3 小时的构建没了
$ ssh server
$ make build       # 网络断了 → 连接关闭 → 构建进程被杀

# 有 tmux：SSH 断开 → tmux server 还活着 → 重连 attach 即可
$ ssh server
$ tmux new -s build
$ make build       # 网络断了 → 重连 → tmux attach -t build → 还在跑

另一个核心能力是多路复用：一个终端窗口里切分出多个 pane（分屏），或者多个 window（类似浏览器标签），不用开一堆终端窗口。

2前缀键模型 · Ctrl-b 与改键

tmux 的所有快捷键都分两步：先按前缀键（默认 Ctrl-b），松开后再按功能键。这样 tmux 的快捷键才不会和终端 / shell / 编辑器的快捷键冲突。设计反直觉是因为你要"告诉 tmux 接下来这句话是对你说的"。

# 操作流程：先 Ctrl-b，再按功能键
Ctrl-b c    # 新建 window
Ctrl-b %    # 左右分屏（vertical split）
Ctrl-b "    # 上下分屏（horizontal split）
Ctrl-b d    # detach（退出客户端，会话继续跑）

# 很多人把前缀改成 Ctrl-a（和 screen 一致，且手指更舒服）
# ~/.tmux.conf
unbind C-b
set -g prefix C-a
bind C-a send-prefix
为什么 Ctrl-b 反直觉？因为它在键盘左下角，小指够起来别扭。改成 Ctrl-a 后手掌自然搭在 home row，按起来快很多——这是 tmux 用户最常见的第一个自定义。

练习：前缀键

3session 生命周期

session 是 tmux 的最顶层容器。一个 tmux server 可以管多个 session，每个 session 有自己的 window 列表。常用命令：

命令作用
tmux new -s name创建 session 并 attach
tmux new -s name -d创建但不 attach（后台）
tmux ls列出所有 session
tmux attach -t nameattach 到指定 session
tmux kill-session -t name销毁 session
tmux new -A -s name存在就 attach，不存在就创建（幂等）

-A 很实用：脚本里写 tmux new -A -s dev，不管 session 在不在都能拿到一个可用的。

练习：session 命令

4window · 类似浏览器标签

每个 session 里有多个 window，底部状态栏会显示编号列表。常用操作（均先按前缀键）：

按键作用
c新建 window
n / p下一个 / 上一个 window
,重命名当前 window
w列出所有 window 供选择
0~9跳到编号对应的 window
&关闭当前 window
# 状态栏示例（* = 当前 window）
[dev] 0:bash* 1:vim 2:htop

练习：window 操作

5pane · 一个 window 里的分屏

pane 是 window 内的分割区域。每个 pane 跑一个独立的 shell。分屏方向容易混：% 是竖线（左右分），" 是横线（上下分）——记忆法：竖线把屏幕分成左右两块，横线分成上下两块。

按键作用
%左右分屏（vertical split）
"上下分屏（horizontal split）
方向键在 pane 之间移动焦点
o跳到下一个 pane
z缩放当前 pane（再按恢复）
x关闭当前 pane
!把当前 pane 拆成独立 window
调试布局推荐：左边一个大 pane 跑编辑器，右边上下两个 pane——上面跑日志 / 下面跑测试。Ctrl-b % 分左右，右边 pane 里 Ctrl-b " 再分上下。

练习：pane 操作

6复制模式 · 终端里的滚动与选择

tmux 有自己的剪贴板（paste-buffer）。按 Ctrl-b [ 进入复制模式：可以滚动回看历史输出、用方向键或 vi 风格移动光标、空格开始选择、回车复制。按 ] 粘贴最近一次复制的内容。

# 进入复制模式
Ctrl-b [

# 默认 emacs 风格移动；配了 vi 模式后：
h j k l       # 方向移动
Space         # 开始选择
v             # 逐字符选择（vi 模式）
Enter         # 复制到 paste-buffer
q             # 退出复制模式

# 粘贴
Ctrl-b ]      # 粘贴最近一次复制

# 多副本管理
Ctrl-b =      # 列出所有 paste-buffer，选择粘贴
set -g history-limit 50000   # 滚动缓冲行数（默认 2000）

如果配了 set -g mouse on，可以直接用鼠标滚轮滚动、拖选复制——但理解底层复制模式在鼠标失灵时能救命。

7配置与手感 · ~/.tmux.conf

tmux 的配置文件是 ~/.tmux.conf，改完后在 tmux 内按 Ctrl-b : 输入 source-file ~/.tmux.conf 重载（或 tmux source-file ~/.tmux.conf）。常用配置：

# 改前缀为 Ctrl-a
unbind C-b
set -g prefix C-a
bind C-a send-prefix

# 启用鼠标（滚轮滚动、点击切 pane、拖拽调整 pane 大小）
set -g mouse on

# 增大滚动缓冲
set -g history-limit 50000

# 从 1 开始编号（默认从 0 开始，0 在键盘最右边不方便）
set -g base-index 1

# 更直觉的分屏快捷键
bind | split-window -h
bind - split-window -v

# 256 色 + true color 支持
set -g default-terminal "screen-256color"

set -g 是全局设置，bind 是绑定按键。配置项非常多，但上面这些覆盖了 80% 的日常需求。

8实战场景 · 远程长任务 / 跨窗口搬文本 / 三面板调试

场景一：远程长任务。SSH 到服务器跑训练 / 构建 / 数据导入，动辄几小时。用 tmux 包住：网络断了不丢，回家 / 换电脑 attach 继续看。

# 到公司
ssh server
tmux new -s train
python train.py          # 跑着...
Ctrl-b d                 # 下班 detach 走人

# 回家
ssh server
tmux attach -t train     # 进度还在，日志还在

场景二：跨窗口搬文本。左边 window 看文档，右边 window 写代码。复制模式选中 → 粘贴，不用切应用。

场景三：三面板调试布局。左边编辑器，右上日志，右下测试。Ctrl-b % 分左右，右边 pane Ctrl-b " 再分上下。Ctrl-b z 可以临时放大某个 pane 看细节。

# 推荐布局：
┌──────────────┬─────────────┐
│              │             │
│   editor     │   logs      │
│              ├─────────────┤
│              │   tests     │
└──────────────┴─────────────┘
