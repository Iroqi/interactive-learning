1HTTP 报文：请求与响应的骨架

HTTP 报文分三部分：起始行（请求行/状态行）→ 头部（键值对）→ 主体（可选数据）。

GET /api/items HTTP/1.1              ← 请求行：方法 + 路径 + 版本
Host: api.example.com               ← 请求头：键: 值
Accept: application/json
Authorization: Bearer abc123

（可选：请求主体）

HTTP/1.1 200 OK                    ← 状态行：版本 + 状态码 + 短语
Content-Type: application/json     ← 响应头

{"items": []}                          ← 响应主体

练习：报文中哪部分携带"我要做什么"？

4状态码：服务器在说什么

状态码是服务器的"脸色"：2xx 成功 · 3xx 重定向 · 4xx 客户端问题 · 5xx 服务器问题。

码含义码含义
200OK 成功401未认证
201已创建403无权限
204无内容404未找到
301永久重定向429请求过多
304未修改（缓存命中）500服务器内部错误

练习：判断场景

6HTTP 无状态：Cookie、Session 与 Token

HTTP 本身不记得你上一次的请求（无状态）。要"记住"用户：Cookie 由服务器下发、浏览器自动带回；Session 把状态存在服务器、只给客户端一个 session id；Token（如 JWT）把状态编码进客户端持有的一串字符里，服务器验签即可。

练习：选正确说法

7REST 设计：资源即 URL，动词即方法

REST 把一切当作资源：URL 指资源，HTTP 方法表操作。好的设计：名词复数（/users）、层级嵌套（/users/5/orders）、用状态码表达结果、保持幂等语义。

练习：哪个设计更好？

8缓存与安全：让 Web 又快又稳

缓存：服务器用 Cache-Control 声明可缓存性，ETag 是资源版本指纹；客户端带 If-None-Match 询问"没变吧？"，没变就回 304。安全：浏览器同源策略阻止跨域读，跨域需要服务器明确允许（CORS 头）；CSRF 靠 SameSite/Token 防护，XSS 靠转义输出。

练习：选正确说法
