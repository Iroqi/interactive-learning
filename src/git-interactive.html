01为什么需要版本控制

版本控制是"给代码拍快照 + 记录快照之间的关系"。没有它，你会陷入 final_v2_really_backup(3).py 的泥潭。

核心心智模型：Git 保存的是完整快照（snapshot），而不是"文件差异"。每次提交都是一次完整的项目快照，只是 Git 用智能的存储方式让它们共享未变化的文件。
随时回退到任意历史版本 并行开发而不互相踩踏 记录谁在何时改了什么 异地协作与备份

proposal_final_v2_really.docx
proposal_final_v3_FINAL.docx
proposal_FINAL_USE_THIS.docx

# 有 Git 之后，一个文件就够了
git commit -m "proposal: 补充预算说明"
git log --oneline   # 历史一目了然

02Git 的对象模型

理解 Git 的关键：一切都是内容寻址的对象 —— 对象的唯一标识就是其内容的哈希值（SHA-1，显示为 40 位十六进制，通常缩写为 7 位）。

为什么"内容寻址"很酷：内容一变，哈希就变 → 对象不可变 → 任何提交的历史都不可能被篡改。分支其实只是一个指向提交的指针，创建分支几乎零成本。
常见误解：Git 不是"只保存差异"（那样历史会纠缠不清），而是保存快照并复用未变化的 blob/tree —— 所以仓库再大，只改一个文件也几乎不增加体积。

03工作区 · 暂存区 · 仓库

Git 有三个区域，文件在它们之间流动：工作区（你看到的文件）→ 暂存区（git add 放入）→ 仓库（git commit 固化快照）。下面动手演练。

三区演练 · 把修改提交成一次快照
把 3 个文件都修改 → 都 git add → git commit，让三个区域回到"干净"状态，即可解锁本步里程碑。
git add index.html   # 把文件快照放入暂存区
git status          # 查看三区状态（练习里会频繁用到）
git commit -m "message"  # 把暂存区固化为一次提交

    07合并与冲突

    合并 = 把两个分支的历史接起来。两种情况：快进合并（main 没有新提交，直接平移指针）和三方合并（需要创建合并提交）。当两个分支修改了同一文件的同一行，就会冲突。

    08撤销与回退

    Git 的"撤销"分三层：工作区（未暂存）、暂存区、已提交的历史。选对命令取决于你想退到哪一层、以及历史能否重写。

    丢弃工作区修改 → git checkout -- <file> 撤出暂存区 → git restore --staged <file> 回退已提交历史 → git reset / git revert
    练习场景：你在 main 上提交了 bug 版本 abc1234，它已推送到远程，同事可能已基于它开发。你想"撤销这次提交但保留历史"，用哪条命令？

    09远程与协作

    10.gitignore：忽略不该入库的文件

    依赖目录、构建产物、本地密钥、日志都不该提交。用 .gitignore 声明忽略规则，git status 立刻清爽。
