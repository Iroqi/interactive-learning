1GraphQL 基础

GraphQL 是 API 查询语言：客户端声明要什么字段，服务端按声明返回，不多不少。三类操作：query（查）、mutation（改）、subscription（订阅）。单一端点 /graphql。

query {
  user(id: "u1") { name email }
}
→ { "data": { "user": { "name": "...", "email": "..." } } }

2类型系统

schema 由类型构成：scalar（Int/String/Boolean/ID）、object（自定义类型）、interface（抽象）、enum、input（参数对象）。! 表示非空。类型定义即契约。

type User {
  id: ID!
  name: String!
  role: Role
  friends: [User!]
}
enum Role { ADMIN USER }
input LoginInput { email: String! password: String! }
本节任务

  • 理解 ! 与列表

3查询语法

查询支持参数（arguments）、别名（aliases，同字段取多次）、片段（fragments 复用字段集）、变量（variables 避免字符串拼接）。操作名利于调试。

query Hero($ep: Episode!) {
  a: hero(episode: $ep) { name }
  b: hero(episode: NEWHOPE) { name }
  ...HeroFields
}
fragment HeroFields on Hero { id name }
本节任务
  • 掌握别名/片段/变量
  • 避免硬编码参数

4Resolver 树

每个字段由一个 resolver 函数解析。解析按字段树深度优先执行：父 resolver 返回值传给子 resolver 的 source。一次查询 = 一棵 resolver 调用树。

Query.user → User.name / User.email / User.posts → Post.title
调用次数 = 查询字段数（叶子越多调用越多）
本节任务
  • 理解字段 → resolver 映射
  • 理解调用树结构

练习：resolver

5N+1 问题与 DataLoader

查询 10 个用户的 posts：若每个 user 的 posts resolver 各自查库 → 1 + 10 次查询（N+1）。DataLoader 在同一 tick 内合并同 key 请求：批量 IN 查询 + 缓存，降到 2 次查询。

无 DataLoader: SELECT user ×1 + SELECT posts ×10 = 11 次
DataLoader:   批量取 posts（WHERE user_id IN (...)）= 2 次
本节任务
  • 能识别 N+1
  • 理解 DataLoader 批量合并

7Mutation 与缓存

mutation 用于写操作，返回变更后的数据让客户端更新本地缓存。规范化的客户端缓存（Apollo/Relay）按类型+ID 存储对象，字段级缓存失效。mutation 需显式声明返回字段。

mutation CreatePost($input: PostInput!) {
  createPost(input: $input) { id title author { name } }
}

8生产实践

生产必做：鉴权（resolver 层做权限，逐字段授权）、深度/复杂度限制（防恶意嵌套查询）、禁用生产内省（introspection）、持久化查询（APQ，白名单）、请求限流与超时。

防护:
- max depth / max complexity 限制
- 生产关闭 introspection
- 持久化查询白名单 (APQ)
- resolver 内做行级权限
