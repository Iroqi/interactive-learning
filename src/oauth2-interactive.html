1角色与令牌

OAuth2 有四个角色：资源所有者（用户）、客户端（App）、授权服务器（发令牌）、资源服务器（API）。access token 是客户端访问 API 的凭证，令牌本身就是访问权限的载体。

用户 (资源所有者)
  └─ 授权 → 客户端 App
        └─ 拿 access token → 请求 API (资源服务器)
              授权/发令牌：授权服务器

2授权码流程

最安全的授权码模式：① 客户端跳转 /authorize；② 用户登录并同意；③ 授权服务器回调 redirect_uri?code=...；④ 客户端用 code + client_secret 换 access token。code 是"一次性票据"，token 只在后端交换，浏览器不接触 token。

GET /authorize?client_id=app&redirect_uri=https://app/cb&scope=profile
    → 302 到登录页 → 用户同意
    → redirect https://app/cb?code=AUTH_CODE
POST /token (code + client_secret)
    → { access_token, refresh_token, expires_in }
本节任务
  • 掌握四步：authorize → code → token → API
  • 理解 code 换 token 为什么要在后端

练习：流程步骤

3PKCE 与隐式流程

隐式流程直接把 token 放 URL 片段，已弃用（token 泄露面大）。PKCE 让公共客户端（SPA/移动端）也安全：客户端先算 code_verifier 的 SHA-256 得到 code_challenge，换 token 时提交 verifier 证明"是我发的 authorize 请求"。

verifier = 随机字符串
challenge = base64url(sha256(verifier))
/authorize?...&code_challenge=challenge
/token?...&code_verifier=verifier   # 证明身份
本节任务
  • 知道隐式流程为何弃用
  • 掌握 PKCE 的 verifier/challenge 配对

练习：PKCE

4scope 与最小权限

scope 声明客户端请求的权限范围（如 profile email）。用户可在同意页勾选/拒绝，遵循最小权限：只申请用到的 scope，令牌权限越少越安全。

scope=profile          # 读基本资料
scope=email            # 读邮箱
scope=offline_access   # 允许发 refresh_token
scope=read:orders      # 业务级自定义 scope
本节任务
  • 理解 scope 是权限声明
  • 遵循最小权限原则

练习：scope

5token 过期与刷新

access token 短时效（分钟级），refresh token 长时效（天级）。access 过期后用 refresh 换新 access——refresh token 只能发给授权服务器，绝不能发给 API 或前端。刷新失败（refresh 过期/吊销）时用户需重新授权。

access token 过期 (401)
POST /token grant_type=refresh_token
    + refresh_token + client 凭据
    → 新的 access token (+ 可轮换 refresh)
本节任务
  • 区分 access（短）与 refresh（长）
  • 知道 refresh token 的存放边界

7常见攻击与防护

① CSRF/登录劫持：用随机 state 参数绑定会话，回调时校验；② redirect_uri 劫持：授权服务器必须精确校验回调地址白名单；③ token 泄露：不放进 URL/日志，HTTPS 传输；④ code 重用：一次性 code 服务端验消耗。

GET /authorize?...&state=随机值
回调 https://app/cb?code=...&state=随机值
客户端校验 state 是否与发起时一致 → 防 CSRF

8OIDC：身份层

OIDC 在 OAuth2 之上加"你是谁"：多返回 id_token（JWT，含 sub/iss/aud/exp）。客户端用 JWKS 公钥验签 id_token，再调 /userinfo 拿资料。OAuth2 管授权，OIDC 管认证。

id_token = JWT {
  iss: 授权服务器, sub: 用户ID,
  aud: client_id, exp: 过期时间, nonce
}
验证：JWKS 公钥验签 + 校验 iss/aud/exp/nonce
本节任务
  • 区分 OAuth2（授权）与 OIDC（认证）
  • 知道 id_token 是签名 JWT，需验签
